# 세 질문과 답변의 시간 — 기록과 변환

실행·시연은 [README](../README.md)의 ‘현재 B’를 참고한다. 질문 원문과 버전, 공통 단위는 [config.js](../modes/questions/config.js)에 있다. 질문을 바꾸면 버전을 올린다. 저장된 질문 원문과 버전은 바꾸지 않으며, 행의 툴팁과 내 원문 확인에서 당시 질문을 확인할 수 있다. 서로 다른 질문 버전은 같은 문항으로 단정해 비교하지 않는다.

## 버전 2 자료

```text
{ schemaVersion: 2, kind: "three-questions-collection", records: [
  { schemaVersion: 2, kind: "three-questions", id,
    source: "participant" | "synthetic", sound: { midi, pan },
    answers: [
      { questionId, questionVersion, question: {ko,en},
        recordingVersion: "dom-composition-v1", text,
        characters: [{ index, char, atMs }], events: [...],
        firstActivityMs, lastTextInputMs, submittedAtMs,
        focusLoss: [{fromMs,toMs,reason}],
        morse: { transformVersion: 1, unitMs: 80,
          originalDurationMs, durationMs, width,
          segments: [...], events: [...] }
      }, ... // Q1, Q2, Q3 順
    ]
  }, ...
] }
```

모든 atMs는 질문이 보이고 입력이 활성화되는 프레임의 performance.now() 기준이다. 브라우저의 DOM/프레임 시각이며 하드웨어 디스플레이·키보드 지연 측정값은 아니다. 첫 활동을 0으로 이동하지 않는다. 제출 시각은 명시적 클릭 후 조합·후속 input이 안정된 뒤 기록하므로 제출 정착에 필요한 짧은 프레임 시간도 포함된다.

`events`에는 beforeinput의 종류·데이터·선택 영역, input의 DOM 값·조합 여부, compositionstart/update/end, activity, commit(추가·삭제·전체 값·선택 영역), blocked, focusout/in을 보존한다. `activity`의 첫/마지막 시각이 요약 필드와 일치하는지 검사한다. focusout과 focusin으로 이탈 구간을 재구성하고 제출까지 닫히지 않은 입력 포커스 구간은 제출 시 닫는다. `input`/`window`/`hidden`은 관측된 이탈 원인이지 심리 해석이 아니다.

공백과 줄바꿈도 최종 문자에 포함한다. Unicode 코드포인트 기준 index를 사용하고 DOM selectionStart/End(UTF-16)는 코드포인트 인덱스로 변환한다. NFC 정규화를 강제로 적용해 입력 시각을 합치지 않는다. 호환 자모와 현대 초·중·종성 자모도 원래 위치를 유지한다.

## IME와 수정 기준

- 물리 keydown으로 한글 문자를 판정하지 않는다. 조합 도중 임시 DOM 값은 원시 활동일 뿐 확정 문자가 아니다.
- compositionend 또는 그 후 실제 확정 DOM input에서 음절이 반영된 시각을 최종 문자에 쓴다. 같은 값의 후속 input은 문자를 추가하지 않는다.
- 새로 확정된 음절은 한 문자이다. 최종 문자열에서 바뀐 구간의 새 문자에 그 확정 시각을 준다. 살아남은 기존 문자 시각은 보존한다.
- beforeinput의 선택 범위를 우선 사용해 같은 문자가 반복된 문장 중간의 삭제도 올바른 위치에 적용한다. 선택 정보가 없으면 앞/뒤 공통 부분의 차이로 범위를 찾는다.
- 최종 텍스트 순서에서 시각이 단조 증가하지 않을 수 있다. 예를 들어 a(100ms), b(200ms)를 입력한 뒤 맨 앞에 c(1000ms)를 삽입하면 최종 문장은 cab이고 문자 시각은 [1000,100,200]이다. 원본은 이 값을 유지하고 모스는 실제 확정 순서 a→b→c로 재생한다. 이는 최종 문장 순서와 시간 순서를 혼동하지 않기 위한 첫 버전의 선택이다.
- 삭제한 문자는 전송하지 않지만 그 활동과 시간은 압축하지 않는다. 마지막 살아남은 문자 이후 삭제·수정이 있으면 해당 시간을 revision-silence로 두고, 그 뒤 마지막 텍스트 활동→제출은 submit-silence로 나눈다.
- 조합 중 제출은 blur로 확정을 요청하고 조합 종료·후속 input을 기다린다. 확정되지 않으면 안내 후 제출하지 않는다. IME Enter로 생긴 줄바꿈은 별도로 차단한다. 일반 Enter는 명시적 제출이 아니며 줄바꿈으로 기록할 수 있다.
- 붙여넣기·드롭·insertReplacementText 및 한 번에 확정된 여러 문자는 blocked 로그로 구분한다. 알 수 없는 글자별 시각을 만들어 넣지 않는다. 동작을 취소/롤백하고 기존 확정 문자열을 유지한다. 입력기/자동완성으로 여러 음절을 한 번에 확정하는 방식은 이번 리듬 기록에서 지원하지 않는다.

## 공식 부호와 명시적 분해 규칙

기본 국문 14자음·12모음은 [중앙전파관리소고시 제2025-1호, 별표 1 PDF 첫 페이지](https://www.law.go.kr/LSW/flDownload.do?flSeq=155599525&bylClsCd=200201)를 시각 대조했다. [고시 본문](https://www.law.go.kr/admRulLsInfoP.do?admRulSeq=2100000262854&chrClsCd=010202)과 [ITU-R M.1677-1](https://www.itu.int/rec/R-REC-M.1677/en)을 출처로 둔다. 발음 로마자화나 임의의 새 한글 부호표를 쓰지 않는다.

완성형 음절을 유니코드 초성·중성·종성으로 분해한 뒤 다음 규칙을 적용한다. 이 **분해와 경계는 앱의 명시적 약속**이며 표에 없는 복합 글자의 독립된 표준 부호를 주장하지 않는다.

| 종류 | 분해 |
| --- | --- |
| 쌍자음 | ㄲ=ㄱㄱ, ㄸ=ㄷㄷ, ㅃ=ㅂㅂ, ㅆ=ㅅㅅ, ㅉ=ㅈㅈ |
| 복합모음 | ㅒ=ㅑㅣ, ㅖ=ㅕㅣ, ㅘ=ㅗㅏ, ㅙ=ㅗㅐ, ㅚ=ㅗㅣ, ㅝ=ㅜㅓ, ㅞ=ㅜㅔ, ㅟ=ㅜㅣ, ㅢ=ㅡㅣ |
| 겹받침 | ㄳ=ㄱㅅ, ㄵ=ㄴㅈ, ㄶ=ㄴㅎ, ㄺ=ㄹㄱ, ㄻ=ㄹㅁ, ㄼ=ㄹㅂ, ㄽ=ㄹㅅ, ㄾ=ㄹㅌ, ㄿ=ㄹㅍ, ㅀ=ㄹㅎ, ㅄ=ㅂㅅ |

기본 표의 ㅐ·ㅔ는 각각 자기 부호를 사용한다. 독립 자모도 같은 분해 규칙이다. 자모 사이에는 3단위, 한글 음절 경계에는 5단위, 영문 문자 사이에는 3단위, 공백/줄바꿈 단어 경계에는 7단위를 둔다. 점/선 내부 간격 1단위, 점 1단위, 선 3단위이다. 기본 단위는 80ms와 4px이다. 미지원 문자는 위치와 3단위 무음 자리(◇)를 유지하며 숨겨서 제거하거나 임의의 소리를 만들지 않는다.

지원 국제 문장부호: `. , : ? ' - / ( ) " = + @`. 그 밖의 부호나 이모지는 입력·원본 기록에는 남고 모스에선 ◇로 표시한다. 혼합 문장은 각 문자의 실제 표를 사용한다.

## 원본과 변환은 서로 다른 시간축

살아남은 문자를 확정 시각으로 정렬한다(동시 확정은 최종 index 순). 실제 첫 확정까지의 시간, 인접 확정 사이 시간, 마지막 확정 이후 수정·제출까지의 시간을 침묵으로 더한다. 그 사이에 부호 묶음과 고정 경계를 추가한다. 그러므로 **실제 침묵을 모두 더한 예술적 변환**이고, 실시간 입력의 정확한 복제가 아니다.

예: A=2000ms, B=3500ms, 제출=5000ms. 원본은 5000ms이다. 80ms 단위에서 A 묶음=400ms, B 묶음=720ms, 문자 경계=240ms라서 변환 길이는 6360ms이다. 첫 침묵 2000ms와 A→B의 1500ms, B→제출의 1500ms를 모두 유지한다. Q1/Q2/Q3에 같은 계산을 한다.

원본 화면의 x는 ms×0.018이다. 모스 화면에서는 실제 침묵의 x도 같은 계수이며, 부호·고정 경계에는 공통 단위 너비를 쓴다. 매번 전체 행을 같은 폭으로 맞추지 않는다. 재생 커서는 변환 segment의 시간에 맞춰 이동한다. 원본 화면에서는 실제 침묵 구간을 이동하고, 해당 부호를 읽는 동안 그 원본 확정 시각에 머문다. 음표시·커서는 위치/크기를 바꾸지 않고 색으로 강조한다.

## 저장·검증과 운영상 한계

새 키 `hello.three-questions.v2`와 v2 envelope를 사용한다. 기존 A/이전 B v1 파일을 임의로 세 답변으로 바꾸지 않는다. 파일 입력은 전체 검증을 끝낸 뒤 합치며 같은 ID는 중복하지 않는다. 파생 morse도 저장하고 다시 계산해 원본과 같은지 검증한다. 잘못된 문자 시각, 로그 순서, 선택 범위, 활동 요약, 포커스 구간, 숫자/시간, 질문 수, 파생 이벤트 오류는 거부한다.

원문과 삭제된 입력의 내용은 JSON/로컬 저장에 포함된다. 기본 화면에서 숨겼다는 것이 암호화나 익명화는 아니다. 운영자가 내보내거나 전체 삭제할 때 이 점을 고려한다. 저장 권한·용량 실패는 메모리 기록과 안내로 처리한다. 브라우저/프로필/포트/file 경로가 바뀌면 저장 공간도 달라질 수 있으므로 발표 전 JSON을 백업한다.

한 기기 최대 20명, 답변 120 코드포인트, 로그 10,000이벤트/답변, JSON 16MB이다. 관객 입력에는 시간 제한이나 자동 제출이 없다. 실시간 반복, 온라인 수집, AI 분석은 이번 범위에 없다. 공통 배율 변경은 원본을 바꾸지 않고 기존 예약을 정지한 뒤 새 재생에 적용한다.

## 실제 수행한 검증과 수동 확인

- `python scripts/verify-browser.py`: 기존 A·이전 B 포함 208/208. 한글 11,172음절, 기본/복합 자모, 삭제/중간 삽입, IME 합성 이벤트 중복/제출, 실제 시간 보존, 합성 예시 재현, JSON·합류·중도취소·모드 정리.
- 실제 OfflineAudioContext: 20명×세 질문 2,419부호 유한 파형, peak 0.1195, 클리핑 없음. 미래 부호를 예약한 뒤 정지한 렌더는 무음.
- `python scripts/verify-questions.py`: HTTP/file://의 실제 Chrome UI 흐름, 실제 AudioContext 예약·완주·모드 취소, 네이티브 새로고침/다운로드/File 입력과 JSON 검사. 여기서의 IME는 합성 이벤트이다.
- `python scripts/verify-downloads.py`: A의 실제 JSON 및 두 WAV 다운로드를 별도 검사한다.
- 수동 확인: Windows/macOS 실제 IME 확정·연속 음절·조합 중 클릭 제출·중간 선택 수정, 스피커/헤드폰의 음색·마스터 음량·좌우·체감 동기, 저사양 기기와 장시간 운영. 확인하지 않은 것을 완료로 주장하지 않는다.
