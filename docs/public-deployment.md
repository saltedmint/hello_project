# 공개 Your Type

배포 주소: **https://your-type-greetings.sweetwasp128.chatgpt.site**. 관객 로그인은 필요 없다. [QR PNG](../presentation/your-type-qr.png)와 [실제 배포 검증 기록](../presentation/verification.md)을 함께 제공한다. 발표자 관리는 같은 주소의 `/admin`에서 소유자 계정으로 로그인한다. 서버·DB 연결을 위해 추가 계정 가입이나 키 입력을 할 필요는 없다.

기존 정적 앱을 유지하고 Sites가 제공하는 Worker ESM + D1에 연결한다. 프레임워크나 음원 서비스를 추가하지 않는다. 개인 체험은 브라우저에서 실행하고, 서버는 완료한 세 답변 저장과 결과 진입 시 누적 조회만 담당한다. 로컬 A·기존 B와 운영 화면은 유지한다.

## 실행과 빌드

기존 로컬 모드: `python -m http.server 8000 --bind 127.0.0.1` 후 `http://127.0.0.1:8000`.

서버 포함 로컬 모드(Node 24 이상, 별도 설치 패키지 없음):

```
node scripts/build-public.mjs
node scripts/test-public.mjs
node scripts/serve-public.mjs
```

주소는 `http://127.0.0.1:8001`. `.deploy/preview.sqlite`가 로컬 DB이며 운영 D1과 분리된다. 로컬 프리뷰는 외부에서 전달한 인증 헤더를 제거하므로 관리 기능은 활성화되지 않는다. 테스트는 SQLite 어댑터를 통해 같은 Worker·검증기·SQL을 사용한다.

`scripts/build-public.mjs`는 현재 소스·공용 검증기와 필요한 자산만 단일 Worker로 묶는다. `dist/`는 생성물이며 Git에 넣지 않는다. `idea/`, 다운로드 폴더, 테스트·문서, 환경변수, Git 메타데이터는 공개 자산으로 제공하지 않는다. GitHub `main`은 변경하지 않는다. `.openai/hosting.json`은 Sites ID와 D1 바인딩 이름 `DB`만 포함한다. Sites 소스 도우미로 커밋/원격 소스를 동기화하고 패키징한 동일 아카이브를 저장·배포한다. `drizzle/`의 스키마 마이그레이션은 배포에서 적용된다. 기존 마이그레이션은 적용 후 수정하지 않는다.

## 체험과 입력

관객은 로그인 없이 HTTPS 주소에서 시작한다. Enter 또는 제목 터치가 시작 조작이며 최초 조작에서 한 AudioContext를 활성화한다. 세 질문은 한 글자씩 출력하고, 영어 번역과 입력이 활성화된 순간부터 `performance.now()`를 기준으로 기록한다. **Enter 한 번 또는 다음/완료 버튼 한 번으로 제출**한다. 한글 조합 중이면 포커스 해제로 네이티브 확정을 요청하고 후속 input을 기다린다. 종료 이벤트가 누락되면 80ms 뒤 현재 DOM을 관찰한 `compositionfinalize` 로그로 최종 답변을 보존한다. 이 시각을 알 수 없는 물리 키 타격으로 바꾸지 않는다. 중복 탭·길게 누르기와 화면 이탈 후 대기 중인 제출은 차단한다.

새 Your Type 기록은 `dom-activity-v3`다. 확인된 물리 키는 원래 keydown 시각을 사용하고, 모바일의 여러 글자 조합 확정이나 단어 교체는 실제 관찰한 변경 한 번으로 기록한다. 여러 글자의 키 타격이나 타이밍을 복원하지 않는다. 붙여넣기·드롭은 계속 차단한다. 기존 v1/v2 기록의 해석은 보존한다. OS별 IME/자동완성은 실제 기기 확인이 필요하다. 네트워크 도착 시각은 타이핑 시각으로 사용하지 않는다.

공개 체험은 첫 침묵·중간 멈춤·제출 전 침묵을 원본 그대로 재생한다. 로컬 시연에 남아 있는 양끝 침묵 상한은 공개 체험에는 적용하지 않는다. 질문 규칙, 점/모스 변환, 음높이·팬·레이어 음량, 9구간과 지속 앰비언스는 공유한다. 마지막 구간 이후 검정 5초가 끝나면 Enter/터치 복귀 버튼을 표시한다.

## 저장과 재시도

`responses` 기본 키는 `(round_id,session_id)`이다. 전체 기록은 기존 schemaVersion 2이며 세 질문의 원문·버전, 답변, 활동·문자·수정·포커스 상대 시각, 기록 버전, 음높이/팬, 실제/더미 구분을 보존한다. 회차와 서버 생성 시각은 서버 열에 저장한다. 시작 시 회차를 고정하므로 진행 중 회차가 바뀌어도 섞이지 않는다. 같은 ID·같은 내용의 재시도는 성공 응답만 돌려주며 다른 내용은 409로 거부한다.

서버는 공통 검증기로 120자, 답변당 1만 로그, 질문 구성/버전, 유한한 숫자·순서, 텍스트와 수정 로그·문자 시각·입력 활동의 일치를 확인한다. POST는 최대 1MB, 질문별 최대 30분이다. 공개 요청으로 더미를 등록하거나 기존 기록을 수정·삭제할 수 없다.

전송 전 전체 기록을 localStorage의 `your-type.outbox.v1`에 보관한다. 저장 응답을 확인한 뒤만 미전송 큐에서 제거한다. 실패 시 메인의 ‘미전송 기록 다시 보내기’로 재시도한다. 브라우저 저장 공간 부족은 메모리에 보존하되 페이지를 닫으면 유실될 수 있음을 표시한다. 서버 저장 성공과 누적 조회 실패를 구분한다. 누적 조회 실패 시 내 기록으로 9구간을 진행하고 처리중 화면에서 상태를 알린다. 네트워크 각 요청은 1.8초 제한이며 개인 입력 시간에는 영향을 주지 않는다.

## 누적 조회와 공개 정보

`GET /api/responses?round=...`는 같은 회차·현재 질문 버전의 최근 20개를 서버 생성 시각 내림차순, 동률이면 세션 ID 내림차순으로 선택한다. 현재 관객 ID를 제외한 최신 19개와 내 기록 1개를 합쳐 최대 20레이어다. 초과한 기록도 DB에는 보존한다. 내 ID는 Map으로 한 번만 포함하고 결과 시작 전에 스냅샷을 확정한다. 재생 중 추가 조회하지 않는다.

공개 응답에는 답변 원문, 문자 배열, 원시 키/수정 로그가 없으며 부호·활동 시각과 소리 설정만 있다. 모스는 본질적으로 문자를 표현하므로 **익명화·원문 비반환이 내용의 기밀성을 보장하지 않는다**. 시작 안내에 민감한 정보를 쓰지 않도록 표시한다. 이름·이메일·가입을 관객에게 요구하지 않는다. 합성 데이터는 `source:synthetic`, `isDemo:true`로 구분하고 포함 시 결과 진입 전에 합성 개수를 알린다.

## 발표자 관리

`/admin` → ‘발표자 계정으로 로그인’. Sites가 검증한 로그인 이메일이 런타임 `ADMIN_EMAIL`과 일치할 때만 서버 관리 API가 허용된다. 관리 페이지 소스를 볼 수 있어도 데이터 권한은 생기지 않는다. 플랫폼 인증 헤더 경계와 서버 권한 검사를 함께 사용한다.

- 회차 ID·제목·더미 포함 여부를 선택하고 전환한다. 진행 중 관객은 시작 시 회차를 유지한다.
- 10인 배치를 반복 추가해도 동일 ID이므로 중복되지 않는다. 해당 회차의 지정 배치만 확인 후 삭제한다.
- 발표 기본 5인 배치 `presentation-5-v1`은 한국어 3명·영어 2명의 15답변이다. `scripts/seed-presentation-five.mjs`로 현재 회차에 명시적으로 한 번 등록하며 반복 실행해도 중복되지 않는다. 관리 화면의 기본 5인 추가/삭제 버튼도 제공한다. 실제 기록·10인 배치와 별도이며 앱 시작 시 자동 재삽입하지 않는다. 현재 발표 회차는 이 배치를 포함하도록 설정한다.
- 전체 회차 JSON 내보내기는 비공개 원문과 로그를 포함한다.
- 회차와 세션 ID를 지정한 개별 삭제만 제공하며 확인을 받는다.

환경변수는 Sites 보안 설정에서만 입력한다. `ADMIN_EMAIL`, `CURRENT_ROUND_ID`는 런타임 설정이다. 선택적인 `ADMIN_API_TOKEN`은 운영 자동 검증/스크립트용이며 브라우저·소스·Git에 넣지 않는다. 이 배포 과정에서는 무작위 토큰으로 검증한다. 발표자가 모르는 토큰을 관리 화면에 입력할 필요는 없다. 필요하면 환경변수 설정에서 제거·교체할 수 있고 이메일 로그인은 유지된다. 키나 비밀번호를 채팅에 붙이지 않는다.

## 검증 구분

`node scripts/test-public.mjs`는 실제 SQLite에 같은 Worker 요청을 보내 입력 검증·권한·영속 SQL·중복 제출·더미·회차/20레이어를 검사한다. 이것만으로 공개 배포나 기기 간 통신을 확인했다고 말하지 않는다.

`scripts/verify-public-browser.mjs`는 Chrome의 분리된 두 저장소 컨텍스트에서 실제 HTTP(S) API에 UI 제출·상호 조회·새로고침·재시도를 검사한다. 검증용 회차는 제목에 합성 자동 검증으로 구분하고, 종료 시 검증 응답만 관리자 권한으로 제거하며 기존 회차를 복구한다. 390px 모바일 화면 크기를 검사하지만 실제 휴대폰이나 가상 키보드 입력과는 다르다. 네트워크 실패 케이스는 fetch 실패 모의 주입임을 구분한다.

실제 휴대폰(iOS Safari/Android Chrome) 터치 시작과 오디오 활성화, 가상 키보드/한글 IME, 노트북 Enter, 실제 이어폰 청취, 모바일 데이터에서 QR 접속, 발표자 실제 로그인과 다운로드는 발표 전에 직접 확인한다.
