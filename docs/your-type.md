# Your Type 시연 흐름

`index.html`은 B의 Your Type 메인으로 시작한다. A·기존 B·질문형 기록 관리 화면은 보존한다. 한국어/영어 질문 표시는 그대로이며 질문 소리는 한국어만 사용한다. Q3 제출 후 자동 저장한다. 세 선택은 사용자 확인으로 확정했다.

## 상태와 입력

명시적 상태는 `main / Q1 / Q2 / Q3 / processing / playing / blackout / ended`이다. `blackout`은 그래픽 없는 검정 5초, `ended`는 복귀 안내 상태이다. `type-experience.js`가 관객 흐름을 담당하며, 기존 `controller.js`는 설정의 운영/JSON 화면에 남아 같은 Store를 사용한다. 분리된 textarea와 리스너를 사용하고 운영 화면에서는 관객 키 핸들러를 비활성화한다.

Enter는 문서 캡처 단계에서 한 번 처리한다. `repeat`와 누름 상태를 함께 확인하며 keyup 전에는 다음 제출을 허용하지 않는다. **Enter 한 번으로 제출을 요청**하며, 한글 조합 중이면 브라우저의 `compositionend`와 후속 input이 처리된 다음 자동 제출한다. 조합이 끝난 Enter는 이전 IME의 `keyCode 229`만으로 차단하지 않는다. 화면 이탈이나 질문 전환 시 대기 중인 제출을 취소한다. 제출 Enter는 beforeinput 줄바꿈을 차단하며 점·문자로 기록하지 않는다. 한국어 질문은 `questionRevealMs`(65ms)마다 한 글자씩 표시하며 그동안 textarea/Enter를 잠근다. 완료 후 영어 번역을 표시하고 두 프레임을 그린 뒤 입력을 활성화하며 새 `performance.now()` 원점을 잡는다. 질문 출력 시간은 기록에서 제외한다. 출력 타이머는 화면 이탈 시 취소한다. 종료 안내가 나와도 Enter 누름 상태를 초기화하지 않아 계속 누르고 있던 키로 복귀할 수 없다.

입력 효과음은 input/compositionend 처리 후 `collectTyping(recorder.events)`의 새 활동만 읽어 재생한다. 이 함수는 기존 점 모드와 같은 규칙이며 효과음은 원시 이벤트/최종 문자/저장 시각을 수정하지 않는다. keydown 단독이나 중복 조합 알림을 소리로 세지 않는다. 공백은 포함하고 삭제/수정키/자동 반복/붙여넣기는 제외한다. 같은 659.25Hz/70ms 사인파에 6ms attack/12ms release를 주며, 새 입력이 이전 음을 끊지 않는다. `typingBus`와 소스 Set은 별도이며 질문 전환/처리중/포커스·탭 이탈에는 이 Set만 정리해 앰비언스를 보존한다. 사운드 미활성화·음소거 때는 입력음을 만들지 않는다.

질문 입력은 기존 Recorder와 `dom-typing-v2`/`dom-composition-v1` 검증을 재사용한다. 원본 ms, 개별 확인 입력 활동, 최종 문자, 수정·포커스 로그와 모스 변환을 보존한다. 문자·자모 시간을 새로 추정하지 않는다. 개별 활동을 제공하지 않는 모바일/IME는 관찰 가능한 DOM 입력 단위만 기록한다. 실제 OS IME 이벤트 순서에는 수동 확인이 필요하다.

Q3 완료 레코드는 같은 ID로 Store.add 한다. 재시도에도 중복하지 않는다. localStorage 실패나 이벤트 준비 오류는 결과 준비 성공으로 취급하지 않고 오류·재시도·완료 답변 JSON 백업을 표시한다. 20명 한도면 입력 시작 전에 안내한다. 실제 기록을 지우거나 자동 교체하지 않는다.

## 9구간과 시간

`type-sequence.js`가 각 질문의 `question / own / together` 세 구간을 Q1→Q2→Q3 순으로 만든다. 질문 생성 데이터는 `kind:generated-question-dots`, `source:question-rule-v1`이며 완성된 한국어 표시 문자와 문장부호 하나당 점 한 번이다. 공백은 소리를 만들지 않고 다음 문자까지의 시작 간격에 200ms를 더한다. 예: `가 나?` → `[0,400,600]ms`. 한글을 자모로 분해하지 않는다. 이 자료는 관객의 타이핑 데이터베이스에 넣지 않는다.

답변은 기존 dots.compile / Morse 변환에 시연용 `type-trim.js`를 적용한다. 앞 침묵은 최대 5000ms, 뒤 침묵은 최대 1500ms이며, 초과 양끝만 잘라낸 파생 점수를 화면과 소리가 공유한다. 모든 타격의 시각에는 같은 앞 제거량만 빼므로 입력 사이 간격은 그대로다. Q별 보정은 없다. 모스의 부호·단어 경계·미지원 문자 구간을 남기고, 외곽 first/revision/submit-silence만 정리한다. 빈 이벤트 점 기록도 과도한 무음 대기로 이어지지 않게 처리한다. 구간 길이는 정리된 점수와 마지막 이벤트 끝 중 큰 값에 안전 꼬리 40ms를 더한다. 그 뒤 400ms(한 상수)의 전환에서 앞 그래픽을 페이드아웃하고 다음 그래픽을 페이드인한다. 원본 내부의 긴 침묵은 잘라내거나 전환으로 판단하지 않는다.

새·기존·불러온 기록에 결과 계획 작성 시 적용하며 localStorage·JSON 원본을 덮어쓰지 않는다. 파생 `edgeTrim`은 `policy`, `leadingRemovedMs`, `trailingRemovedMs`, `originalDurationMs`를 제공한다. 기록 관리 화면은 원본 시각으로 비교한다. 요청에 따른 양끝 정리는 기존의 무보정 재생 정책에 대한 명시적 예외이다. 원본 자료에서 시각을 역산하거나 음 이벤트를 추가하지 않는다.

결과 시작 시 모든 입력을 검증·복제하고 ID Map으로 중복을 제거한다. 더미 포함 여부는 세션 설정을 사용하며, 현재 관객은 항상 한 번만 넣는다. 이후 Store나 숨겨진 설정이 변해도 재생 계획은 변하지 않는다. 전체 9구간의 시작을 공통 AudioContext 시각에 상대 오프셋으로 예약한다. 무음 선택이면 AudioContext를 만들지 않고 performance.now 시계를 사용한다.

기존 row 렌더러를 재사용하되 라벨·원문·툴팁·커서를 제거한다. 질문은 고정 점, 답변은 점 또는 모스, 함께는 사람별 행이다. 중앙 배치는 전체 행의 실제 부호 범위로 계산하고 공통 바깥 빈 공간만 레이아웃에서 제외한다. 행마다 다른 기준점이나 폭 정규화를 쓰지 않는다. 내부 간격과 사람별 시작 시각 차이는 같은 비례계수를 유지하며, 재생 강조도 조정 점수와 일치한다. 끝 침묵에는 빈 스크롤 공간으로 이동하지 않는다. 많은 사람은 세로 행 높이만 조정한다. 강조는 크기·위치를 바꾸지 않는다. 9구간의 마지막 음과 꼬리가 모두 끝나면 그래픽을 제거한다. `endingDelayMs`(5000ms) 동안 완전 검정으로 대기하고 그 후 복귀 안내만 표시한다. 대기 중 Enter와 안내 전부터 누른 Enter는 무시한다. 종료/질문 타이머도 generation 검증과 clearTimeout으로 취소한다.

## 오디오 수명

`type-sound.js`의 한 AudioContext와 마스터/컴프레서 아래에 ambienceBus / mainBus / resultBus / typingBus를 둔다.

- 앰비언스: 낮은 사인파 3개와 느린 비주기적 gain 변조. 화면 상태마다 생성하지 않는다.
- 메인: 장식용 임의 점/선과 같은 시각에 짧은 사인파. 실제 관객 기록과 분리한다. 진입마다 하나의 스케줄러만 유지하고 질문 진입 시 180ms 내 짧게 페이드 종료한다.
- 결과: 기존 Player에 output bus를 주입한다. 구간별 실제 레이어 수의 제곱근으로 gain을 보정하고 메인 마스터를 거친다. 결과 정지는 이 Player의 소스/출력만 끊는다.
- 입력 효과음: 확인된 새 입력 활동만 짧게 울린다. 입력과 결과는 같은 원본 활동 기준을 사용하지만 라이브 효과음은 즉시 시작하고, 결과는 저장된 원본 시각으로 예약한다. 입력음 생성은 기록을 보정하거나 결과 이벤트를 추가하지 않는다.

첫 사용자 클릭 전에는 오디오 장치·자동 재생을 만들지 않는다. 한 번 활성화하면 정상 메인 복귀에는 다시 클릭을 요구하지 않는다. 전체 음소거는 공통 마스터 gain이므로 네 레이어 모두에 적용된다. A/운영 화면 이동 및 페이지 이탈에는 모든 소스·타이머·리스너·RAF를 정리한다. 같은 B 체험 내부의 메인 복귀/종료 검정 대기에서는 앰비언스를 유지한다. 탭 숨김은 컨텍스트/무음 시계를 일시정지하여 이벤트 몰아 재생을 방지한다.

## 실행과 검증

`python -m http.server 8000 --bind 127.0.0.1` 후 `http://127.0.0.1:8000`을 연다. 기존 file 직접 실행도 유지한다. 저장소는 브라우저·origin별 localStorage이며 다른 URL/프로필로 옮길 때 JSON을 백업한다.

- `python scripts/verify-browser.py`: 257/257 통과. 기존 A·이전 B·질문 데이터/운영 기능과 Your Type 상태·Enter·IME 합성 이벤트·오류 재시도·스냅샷·레이어 수명, 순차 질문/입력 원점·효과음·검정 대기·늦은 안내 콜백 취소를 검증했다.
- `python scripts/verify-your-type.py`: 격리된 실제 Chrome에서 처리 5초와 종료 검정 5초를 실제로 기다리고 9개 구간을 끝까지 재생했다. HTTP는 실제 AudioContext에서 입력 활동 10개/효과음 10번 일치를 확인했으며, file은 AudioContext 없는 무음 시계로 완주했다. 질문 출력 시간은 첫 침묵에 포함되지 않았다. 한국어 입력은 합성 DOM 이벤트이며 실제 OS 입력기가 아니다. 원본 질문/답변·더미 16명·현재 관객 1명 JSON 다운로드도 검사했다.
- `python scripts/verify-questions.py`: 기존 운영 화면의 입력·모스·새로고침·JSON 호환 검증.
- `python scripts/verify-downloads.py`: A의 네 마디·손글씨·WAV 실제 다운로드 검증.

양끝 침묵 검증에는 원본 `[30000,30300,40000]ms`/제출 `90000ms`가 시연에서 `[5000,5300,15000]ms`와 끝 `16580ms`로 바뀌는 경우를 포함한다. 내부 300ms·9700ms 간격과 타격 수는 유지된다. 실제 오프라인 오디오에서 첫 5초 무음·조정 시각 발음·끝 무음을 확인했다. Q1 제출 전 약 90초 대기를 재현한 DOM에서 부호 중앙과 빈 꼬리 스크롤 제거, 여러 관객의 공통 기준점도 검증했다. 원본 JSON은 전후 동일하다.

수동 확인: 실제 Windows/macOS IME 확정 Enter/새 Enter/키 반복, 브라우저의 실제 클릭 활성화 정책, 스피커/헤드폰의 앰비언스·결과 밸런스·메인 페이드·좌우 위치·무음, 긴 실제 답변과 20명 결과의 체감 가독성, OS 오디오 중단·탭 비활성화 및 장시간 운영. 자동 파형/DOM 검증은 실제 청취·하드웨어 입력을 대신하지 않는다.
