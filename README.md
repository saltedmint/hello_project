# hello / experiments

인사와 응답의 시간을 음악·타이포그래피·모스로 표현하는 데스크톱 키보드용 로컬 프로토타입입니다. A는 기존 타악기·손글씨 선율, 현재 B는 **세 질문과 답변의 시간**입니다. 기존 `hello stranger`와 임의 문장 실험도 **이전 B 실험**으로 보존했습니다. 외부 라이브러리·빌드·API 키가 필요하지 않습니다. 음원과 폰트를 로컬에 포함했으며, 실행 중 외부 서버로 요청하지 않습니다.

## A · B 모드와 현재 범위

기본 시작 화면은 B의 Your Type입니다. 하단 설정에서 A와 기록 관리로 이동하며, 기존 모드 메뉴도 보존합니다.

| 모드 | 목적 | 현재 구현 |
| --- | --- | --- |
| A · 인사 오케스트라 | 개인의 리듬을 타악기와 손글씨 선율로 표현 | 기존 네 마디 입력, 타악기, 반복 재생, 자간, 선택적 손글씨, WAV 유지 |
| B · Your Type | 질문을 읽고 응답하기까지의 침묵과 수정을 남기는 관객 경험 | Enter로 세 답변, 5초 처리, 질문/내 답변/함께 답변 총 9구간 자동 재생, 점/모스, v2 저장·JSON |
| 이전 B 실험 | 같은 문구/다른 문장의 간격 비교 | hello stranger·임의 문장, 자간/모스, 기존 반복 재생·v1 저장 유지 |

A와 이전 B의 v1 기록, 질문형 B의 v2 기록은 별도로 검증·저장합니다. 이전 기록을 질문 답변으로 변환하지 않습니다. 입력에는 오디오 장치가 필요 없으며 ‘듣기’ 클릭에서 AudioContext를 활성화합니다. 모드 전환은 이전 소리·예약·타이머·애니메이션·입력 리스너를 정리합니다. A 완료 기록은 페이지 메모리, B 누적 기록은 각자의 localStorage에 보존합니다.

## 현재 B · 세 질문과 답변의 시간

`index.html`을 Chrome/Edge에서 열면 **Your Type 메인**으로 바로 시작합니다. 서버 실행은 프로젝트 폴더에서 다음과 같습니다. 이후 <http://127.0.0.1:8000>에 접속합니다. `file://` 직접 실행도 지원하지만 저장소가 서로 다르므로 발표에는 같은 브라우저·URL을 사용하세요.

```powershell
python -m http.server 8000 --bind 127.0.0.1
```

관객 흐름은 **메인 → Q1 → Q2 → Q3 → 처리중 5초 → 9개 구간 자동 재생 → 완전 검정 5초 → 복귀 안내 → 새 Enter로 메인**입니다. 처음에는 작은 **사운드 켜기** 버튼을 클릭할 수 있습니다. 켜지 않아도 무음으로 끝까지 진행하며, 메인 복귀마다 다시 클릭할 필요는 없습니다. 한국어/영어로 짧게 답하고 **Enter 한 번으로 제출**합니다. 한글 조합 중이면 같은 Enter로 브라우저의 조합 확정과 후속 input을 기다린 뒤 자동 제출합니다. 마지막 음절을 확정하기 위해 별도로 Enter를 누를 필요가 없습니다. 빈 답변·자동 반복은 제출하지 않습니다.

한국어 질문은 **65ms마다 한 글자씩** 표시합니다. 출력 중 입력창과 Enter 제출을 잠그며 Enter로 출력을 건너뛸 수 없습니다. 출력이 끝나면 영어 번역을 표시하고, 전체 문장이 그려진 다음 입력을 활성화해 포커스합니다. **입력 가능한 이 순간이 0ms**이며 질문 출력 시간은 첫 침묵에 넣지 않습니다. 이 연출은 의도적인 변경이지만 실제 입력의 첫 침묵·멈춤·수정·제출 시각을 보정하지 않습니다.

입력 중에는 부호·시간 수치를 표시하지 않고, **확인된 텍스트 입력 활동마다 같은 659.25Hz/70ms 전자음**을 냅니다. 기존 점 모드의 중복 제거 목록을 그대로 읽으므로 한글 조합의 관찰 가능한 개별 활동은 반영하되 composition/input 알림마다 중복 발음하지 않습니다. 공백은 포함하며 수정키·제출 Enter·자동 반복·붙여넣기는 제외합니다. 사운드 미활성화/전체 음소거이면 들리지 않습니다. 이전의 ‘입력 중 무음’ 규칙은 Your Type 관객 입력에서 이 동작으로 대체하며, 기존 A와 기록 관리 화면의 입력 정책은 유지합니다.

Q3 제출 후 완성된 세 답변을 **같은 ID로 자동 저장**합니다. 준비 실패는 오류·재시도·답변 JSON 보관을 표시하고 결과로 넘어가지 않습니다. 처리중 Enter는 건너뛰기가 아닙니다. 정상 준비는 화면 표시 후 5초를 유지합니다. 저장 한도 20명에 도달하면 메인에서 먼저 정리를 안내하며 기존 기록을 자동 삭제하지 않습니다.

결과는 **Q1 질문 → 내 Q1 → 내 Q1+다른 관객 Q1 → Q2 질문 → 내 Q2 → 함께 Q2 → Q3 질문 → 내 Q3 → 함께 Q3** 순서입니다. 원문·질문·숫자·버튼 없이 부호 그래픽만 보입니다. 질문 소리는 **표시된 한국어 질문만**, 공백을 제외한 완성 음절·문장부호 하나당 80ms 점 한 번, 시작 간격 200ms, 공백에 추가 200ms입니다. 영어 번역은 질문 화면에 병기하지만 질문 소리로 중복 재생하지 않습니다. 이는 실제 타이핑이 아닌 `question-rule-v1` 생성 이벤트이며 관객 기록으로 저장하지 않습니다.

결과 시작에 기록을 복제·확정하고, 현재 관객은 함께 구간에 한 번만 포함합니다. 입력 사이 간격과 기존 모스 부호는 보존하며, 시연의 양끝 침묵만 아래 규칙으로 정리합니다. 마지막 음·정리된 구간이 끝난 뒤에만 400ms 페이드 전환을 합니다. 재생 중 Enter는 무시합니다. **9구간의 소리와 꼬리가 모두 끝나면 마지막 그래픽을 지우고 완전 검정으로 5초 대기**합니다. 그 뒤 중앙에 ‘엔터키를 눌러 메인 화면으로 돌아가세요’를 표시합니다. 안내 전 Enter는 무시하고, 이전부터 누른 Enter도 복귀를 일으키지 않습니다. 안내가 나온 뒤 키를 뗐다가 새로 누른 Enter만 복귀합니다. 메인 복귀·A 이동·페이지 이탈 시 안내/질문 타이머와 재생 예약을 정리합니다. 이전의 ‘마지막 그래픽 유지’ 동작은 대체했습니다.

### 긴 앞뒤 침묵과 그래픽 중앙 배치

Your Type 시연에서는 **앞 침묵 최대 5초, 뒤 침묵 최대 1.5초**만 남깁니다. 기존 저장 기록·새 입력·JSON 불러오기 모두 재생 계획을 만들 때 자동 적용합니다. 초과한 양끝만 제거하며 입력 사이의 멈춤, 타격 수, 음 길이, 문자/부호는 바꾸지 않습니다. 점·모스의 화면과 소리는 같은 조정 시각을 사용합니다. 질문용 규칙적 점과 A 모드는 이 정리 대상이 아닙니다.

긴 마지막 입력→제출 대기까지 전체 너비로 계산하면 부호가 왼쪽에 몰릴 수 있었습니다. 이제 중앙 배치는 **실제로 보이는 점·선·미지원 문자 표시의 범위**로 계산합니다. 여러 사람은 하나의 공통 기준점과 비례계수를 사용하며, 각 행을 따로 중앙 정렬하거나 폭을 압축하지 않습니다. 긴 중간 간격은 그대로 가로 이동으로 확인하고, 끝 침묵 동안 빈 공간만 있는 곳으로 스크롤하지 않습니다.

저장 원본을 삭제하거나 시각 로그를 다시 쓰지는 않습니다. 원본 JSON과 기록 관리의 비교 재생은 기존 시각을 유지하고, Your Type용 파생 점수에 `edgeTrim`(제거한 앞/뒤 ms·원래 재생 길이)을 남깁니다. 따라서 특정 브라우저 기록을 직접 수정하지 않아도 페이지 새로고침 후 기존 긴 꼬리 기록에 적용됩니다. 임계값은 `type-config.js`의 `edgeLeadingMaxMs:5000`, `edgeTrailingMaxMs:1500`에서 조정하며 구현은 `type-trim.js`에 있습니다. 이번 요청으로 초과한 양끝 침묵의 시연 재생은 기존 무보정 정책의 예외가 됩니다.

화면 하단 **설정**에서 기본 **타이핑 점** / 모스, 10인 더미 추가·배치만 확인 후 삭제, 더미 포함, 마스터 음량·음소거를 선택합니다. 설정 안의 Enter는 체험을 시작하지 않습니다. 시작 시 설정을 확정하여 해당 세션 동안 유지합니다. **기록 관리 · JSON**에는 기존 비교·필터·예시·전체 JSON 관리 화면이 그대로 있으며, **A · 인사 오케스트라**로 이동할 수 있습니다. 기존 A와 이전 B는 기존 모드 메뉴에서도 유지합니다.

지속 앰비언스는 작은 사인파 3개와 느린 gain 변조로 합성합니다. 메인→질문→처리중→결과→검정 대기→메인 사이에 끊거나 처음부터 다시 시작하지 않습니다. 메인 장식 부호/배경음은 별도 gain·스케줄러로 메인에서만 실행하고 질문 진입 시 짧게 페이드 종료합니다. 결과음과 입력 효과음도 각각 별도 bus/소스 목록을 사용하며, 결과/입력 정리가 앰비언스를 끄지 않습니다. 네 레이어 모두 공통 마스터 음량·음소거를 거칩니다. 질문 전환·처리중·창/탭 이탈 때 남은 입력 효과음을 종료하고, A 이동·페이지 이탈 때 전체를 정리합니다. 숨겨진 탭에서는 공통 오디오 시계를 일시정지하고, 무음 진행 시계도 숨겨진 시간을 제외하여 지난 이벤트를 몰아 재생하지 않습니다.

상수는 [`modes/questions/type-config.js`](modes/questions/type-config.js)에 있습니다. 질문 출력 `questionRevealMs:65`, 종료 대기 `endingDelayMs:5000`, 입력음 `typingToneMs:70`·`typingHz:659.25`·`typingGain:.14`를 한곳에서 조정합니다. 기존 처리 5000ms, 전환 400ms와 결과용 질문 200ms/공백 추가 200ms/소리 80ms는 그대로입니다. [구조·검증 설명](docs/your-type.md)을 참고하세요.

질문 원문과 버전은 **`modes/questions/config.js`의 `questions`**에서 수정합니다. 문구를 바꿀 때 해당 질문의 `version`도 올리세요. 기록에는 당시 질문 원문과 버전을 함께 저장합니다.

### 기록 기준과 두 시간축

- 질문이 화면에 표시되고 textarea 입력이 활성화되는 프레임의 `performance.now()`를 0으로 둡니다. 실제 디스플레이/OS 지연까지 측정하는 장치는 아닙니다.
- `beforeinput/input`, `compositionstart/update/end`를 원시 활동 로그에 남기고, 완성된 DOM 텍스트가 확정될 때 최종 문자에 시각을 배정합니다. **물리적 자모 키 타격 시각과 음절 확정 시각은 다릅니다.** 조합 중 활동은 첫 활동 시간에 반영하고, 후속 동일 input은 문자를 중복 추가하지 않습니다.
- 각 질문에 `questionId`, `questionVersion`, 질문 원문, 최종 답변, `recordingVersion`, 원시 `events`, 최종 `characters[{index,char,atMs}]`, `firstActivityMs`, `lastTextInputMs`, `submittedAtMs`, `focusLoss` 및 별도의 `morse` 파생 결과를 저장합니다. 모든 시각은 질문 시작 기준 상대 ms입니다.
- 삭제한 문자는 최종 부호에서 제외하지만 수정 시간은 없애지 않습니다. 중간 삽입/수정은 선택 영역을 참고해 기존 문자 시각을 보존합니다. **재생은 살아남은 문자의 실제 확정 순서**이며, 중간 삽입이 있다면 최종 문장의 왼쪽→오른쪽 순서와 달라질 수 있습니다. 원문과 각 문자의 위치·시각은 별도로 확인할 수 있습니다.
- 첫 활동 전 침묵, 최종 문자 확정까지의 조합 시간, 중간 멈춤, 수정 후 남은 시간, 마지막 활동→제출 시간을 보존합니다. 포커스 이탈 구간은 별도 로그와 원본 시간축의 빗금으로 표시하며 고민으로 해석하지 않습니다.
- 붙여넣기·드롭·자동완성 및 한 번에 확정된 여러 문자는 차단/구분하고 직접 입력을 안내합니다. 글자별 시각을 추정하지 않습니다. 조합 중 제출은 확정과 후속 input을 기다립니다. 브라우저가 확정하지 않으면 강제 확정이나 제출 없이 안내합니다.
- 원본 시간축의 공통 비례계수는 `pixelsPerMs`(기본 0.018px/ms)입니다. 첫 글자를 0으로 옮기거나, 사람·질문별 같은 너비로 정규화하지 않습니다.
- 모스 시간축은 **첫 확정 문자 전 침묵 + 고정 단위 부호 묶음 + 실제 문자 간 간격을 더한 침묵 + 마지막 문자 이후 수정 시간/제출 전 침묵**입니다. 원본 전체 침묵의 합은 원래 제출 시각과 같고 여기에 부호와 고정 경계를 더합니다. 따라서 모스 변환 길이가 더 길며 **원본 타이핑의 정확한 실시간 재생이 아닙니다.** 질문 번호에 따른 보정은 없습니다.

### 한글·영문 부호와 재생

영문·숫자·기본 문장부호는 [ITU-R M.1677-1](https://www.itu.int/rec/R-REC-M.1677/en), 한글 기본 자모 26개는 [중앙전파관리소 「무선국의 운용 등에 관한 규정」 별표 1](https://www.law.go.kr/LSW/flDownload.do?flSeq=155599525&bylClsCd=200201)의 첫 페이지를 대조했습니다. **발음 로마자 변환을 하지 않습니다.** 완성형 음절은 초성·중성·종성으로 분해합니다. 쌍자음은 기본 자음을 반복하고, 복합모음·겹받침은 기본 자모 순서로 풀어 보냅니다(예: ㄲ→ㄱㄱ, ㅘ→ㅗㅏ, ㅙ→ㅗㅐ, ㄳ→ㄱㅅ, ㅄ→ㅂㅅ). 표에 단독 부호가 있는 ㅐ·ㅔ는 그 부호를 사용합니다. 독립 호환/현대 자모도 처리합니다. 전체 분해 규칙과 기록 형식은 [상세 문서](docs/three-questions.md)를 참고하세요.

점 1단위·선 3단위, 부호 내부 1단위, 자모 사이 3단위, 한글 음절 사이 5단위(영문 문자 3단위), 단어 경계 7단위를 사용합니다. 단위는 80ms/4px이며 **자모 분해와 경계는 이 프로토타입의 명시적 변환 규칙으로, 완전한 표준 국문 송신 절차를 재현한다는 뜻이 아닙니다.** 미지원 문자는 ◇ 위치와 무음 자리로 남기며 임의 모스 부호를 만들지 않습니다.

검정 배경의 Q1·Q2·Q3 구역에 같은 질문의 관객별 행을 쌓습니다. 기본 누적 화면에는 원문이 없고, 내 응답 확인 또는 운영자 원문 표시에서만 선택적으로 봅니다. 모스는 암호화가 아니므로 익명화·비밀 보장을 주장하지 않습니다. JSON과 로컬 기록에는 원문·삭제/수정 내역도 포함됩니다.

기록 관리 화면의 비교 재생은 **Q1 → Q2 → Q3** 순서의 한 번 재생이며, 각 질문 안에서는 관객 시작을 공통 0에 맞춥니다. Your Type 관객 시연은 앞서 설명한 별도 9구간 순서입니다. 비교 재생은 가장 긴 변환 응답과 끝 침묵까지 재생합니다. 랜덤 오프셋·무음 제거·질문별 음색 보정·실시간 반복은 넣지 않습니다. 개인별 음높이/약한 pan은 보존하고, 같은 사인파 음색의 길이로 점·선을 구분합니다. AudioContext 공통 시계와 미리 예약을 사용하며 정지·모드 전환·다음 관객·이탈 시 음원과 애니메이션을 취소합니다.

### 발표 시연과 저장

다음 비교/JSON 도구는 **Your Type 설정 → 기록 관리 · JSON**에서 엽니다. 관객용 9구간 화면에는 표시하지 않습니다.

1. **발표 · 운영 도구 → 발표용 합성 데이터 10명 등록**. 한국어 5명·영어 5명, 현재 질문에 대한 총 30답변을 추가합니다. 등록 후 `발표용 합성 데이터 10명 · 30답변`을 확인하세요. 앱 시작 시 자동 삽입하지 않습니다. **기존 합성 예시 6명 불러오기**도 별도로 유지하며, 이 예시에는 혼합 언어·수정·포커스 이탈·가설 반례가 있습니다.
2. 비교 선택에서 한 사람을 골라 세 질문을 비교한 뒤, 여러 관객 선택으로 같은 질문의 행들을 비교합니다.
3. **원본 시간축 / 모스 변환 결과**를 전환합니다. 긴 행은 가로 이동할 수 있으며 재생 표시가 점·선과 침묵을 따라갑니다.
4. Q별 듣기 또는 **Q1 → Q2 → Q3 듣기**를 실행합니다. 공통 속도 0.5·1·2·4×는 모든 질문·관객에 같은 배율이며 원본을 바꾸지 않습니다. 변경 시 기존 재생을 정지하고 다시 듣습니다.
5. **발표 배치 10명만 제거**는 확인 후 해당 배치만 제거합니다. **기존 6명 예시만 제거**도 별도로 확인하며 새 배치와 실제 기록은 유지합니다. 관객은 자기 응답 확인 후 명시적으로 합류하고 다음 관객을 시작합니다.

### 발표 배치 seed와 실제 등록

이 프로젝트의 데이터베이스 역할은 **현재 브라우저·현재 origin의 localStorage**(`hello.three-questions.v2`)가 합니다. 서버 DB·접속 정보는 없습니다. 이번 개발에서는 **격리된 Chrome 프로필에서 실제 저장·복원 조회를 검증했으며, 사용 중인 브라우저에는 연결되지 않아 미리 등록하지 못했습니다.** 위 등록 버튼을 한 번 누르면 그 브라우저 저장소에 등록됩니다. 발표에 사용할 브라우저/URL에서 등록하세요. `file://`, `localhost`, `127.0.0.1`, 포트·프로필 변경은 같은 저장소라고 가정하면 안 됩니다.

재현 가능한 seed는 [`modes/questions/demo-seed.js`](modes/questions/demo-seed.js)입니다. `HelloQuestionDemo.buildBatch()`는 항상 같은 10명·30답변을 생성하고, `HelloQuestionDemo.seed(HelloQuestions.store)`는 UI 버튼과 같은 등록/조회 절차를 실행합니다. 고정 ID `presentation-10-v1-01`…`-10`, `isDemo:true`, `demoBatchId:"presentation-10-v1"`, `source:"synthetic"`를 JSON에도 보존합니다. ID 중복은 건너뛰며 기존 실제/예시 기록을 덮어쓰지 않습니다. 남은 20명 한도에 10명이 들어가지 않으면 기존 기록을 그대로 두고 배치 전체를 거부합니다. 배치 제거는 `demoBatchId`만 대상으로 하며, 이후 같은 버튼으로 재등록할 수 있습니다.

배치는 작품 설명을 위한 **발표용 합성 데이터**입니다. Q1 첫 침묵 0.5–2초·활동 간격 100–300ms, Q2 2–5초·150–500ms와 중간 1–2초 멈춤, Q3 5–12초·200–700ms와 중간 2–5초 멈춤을 사람·문장별로 달리 설계했습니다. 한글은 초성→중성→종성/복합 조합의 가상 DOM 입력 과정을 생성하며 영문 키 로그로 위장하지 않습니다. 이 시나리오는 실제 관객의 속도나 질문별 시간을 보정하는 로직과 분리되어 있습니다. 실제 입력에는 같은 시간 기록 로직만 적용하고 지연·정규화를 넣지 않습니다.

**더미만 보기 / 실제만 보기 / 함께 보기** 필터는 재생 대상에도 적용됩니다. 더미에는 새 발표 배치와 기존 `source:synthetic` 예시가 포함됩니다. JSON 저장은 필터와 무관하게 전체 기록을 백업합니다.

### 모스 모드와 타이핑 점 모드

**표현**에서 모스 모드 / 타이핑 점 모드를 선택합니다. 같은 원본 기록을 사용하며 모드 변경은 예약된 소리·RAF·강조를 정지합니다. 관객·질문·필터 선택은 유지하고, 다음 듣기는 선택한 질문의 처음부터 재생합니다. 원본 데이터는 수정하지 않습니다. 공통 속도 0.5·1·2·4×와 표시 배율은 모든 관객·질문에 동일하게 적용합니다.

| | 모스 모드 | 타이핑 점 모드 |
| --- | --- | --- |
| 이벤트 | 기존 한글·영문 부호의 점/선 | 관찰된 텍스트 입력 활동 한 번당 점/소리 한 번 |

새 기록은 `recordingVersion:"dom-typing-v2"`와 `typingActivities[{atMs,eventIndex,keyEventIndex,unit}]`를 저장합니다. text를 실제로 만든 input으로 확인된 키만 keydown 시각을 사용합니다. keydown·beforeinput·compositionupdate·input·compositionend를 각각 별도 타격으로 세지 않습니다. 공백·삭제되기 전의 타이핑 활동은 남고, Shift/Ctrl/방향키/Enter·Backspace/Delete·자동 반복은 점에서 제외합니다. 수정은 원시 로그로 보존합니다. 붙여넣기·자동완성의 여러 타격 시각은 생성하지 않습니다.

물리 키와 대응하지 않는 IME/모바일 이벤트는 **실제 관찰된 DOM 값 변화 한 번**을 `observed-input`으로 기록합니다. `Process`/229 키도 글자 키 code와 input 확인이 있을 때만 연결하며 자모 타격을 역산하지 않습니다. IME가 여러 키를 한 input에 합쳐 제공하면 개별 키를 모두 알아낼 수 없습니다. 새 기록의 `입력 활동 기록 사용`은 모든 활동이 물리 키 측정이라는 뜻이 아닙니다. **기존 `dom-composition-v1`은 최종 문자의 확보된 시각만 사용하고 `문자 단위 기록 사용`을 행마다 표시**합니다. 과거 `activity` 로그는 중복 조합 활동이 섞여 있어 타격 수로 재해석하지 않습니다.

질문형은 `schemaVersion:2`, `kind:"three-questions-collection"`, localStorage 키 `hello.three-questions.v2`로 구분합니다. 최대 20명, 답변당 120개 코드포인트, JSON 16MB이며 입력 시간 제한은 없습니다. 저장 실패 시 메모리 기록을 유지하고 백업을 안내합니다. 손상된 저장 원본은 자동 삭제하지 않습니다. JSON은 형식·숫자·시간·원문/수정 로그/최종 문자·변환 결과 일치까지 검증한 뒤 ID 중복 없이 추가합니다. 파일 실패 시 기존 기록을 유지합니다. 복원 후 자동 재생하지 않습니다. 전체 삭제는 확인 후 수행하며 A·이전 B 기록은 건드리지 않습니다. 데이터/저장은 `modes/questions/data.js`, 입력은 `input.js`, 변환은 `morse.js`, 오디오는 `audio.js`, UI는 `controller.js`로 분리했습니다.

## B · 인사 사운드스케이프 사용

2. 완성된 자간 미리보기를 확인하고 **풍경에 보태기**를 누릅니다. 제출 전 기록은 누적되지 않습니다. 다음 참가자는 다시 ‘인사 입력하기’를 누릅니다. 오타·조합·붙여넣기·자동 반복은 제외하며, 수정은 처음부터 다시 합니다. 입력을 시작하면 기존 재생을 정지해 조용하게 기록합니다.
3. **전체 듣기 · 사운드 시작** 또는 기록별 **한 기록만 듣기**를 누릅니다. **정지**까지 반복합니다. 개별 듣기는 해당 기록만으로 반복 구간을 계산하며, 전체 듣기로 돌아가면 전체 기록을 사용합니다.
4. **자간 / 모스**는 같은 데이터와 재생 시계를 사용합니다. 전환으로 소리나 기록을 초기화하지 않습니다. 오래된 행도 최소 58% 불투명도로 유지합니다.
5. 왼쪽 **같은 문장으로 실험하기**의 **예시 트랙 수**에서 1·5·10·20개를 선택하고 **hello stranger 예시 추가**를 누르면 같은 문장의 서로 다른 리듬을 시험할 수 있습니다. 기본 10개가 서로 다른 간격을 가진 합성 기록이며, 20개 시험에는 추가 10개 변형을 사용합니다. ID가 고정되어 중복 로딩되지 않으며 모두 ‘실제 참여자 아님’으로 표시합니다. 기존 기록은 덮어쓰지 않으며 합계 20개를 넘으면 전체 추가를 거부합니다.

### B 소리·시각화·반복 규칙

**다른 문장으로 실험하기:** 왼쪽 패널에서 1·5·10·20개를 선택하고 **임의 문장 · 리듬 추가**를 누른 뒤 **전체 듣기**로 들어보세요. 준비한 24개의 소문자 영문 문장 중 겹치지 않게 선택하고, 사람별 기본 속도·글자별 편차·단어 경계의 쉼·가끔 긴 망설임을 난수로 생성합니다. 클릭할 때마다 새 결과를 만들며 실제 키보드 입력이나 실제 참여자 기록이 아닙니다. 재생 중 추가하면 다음 반복 경계에서 합류합니다. 기록 한도는 기존과 합쳐 20개이며 남은 공간만 채우고 기존 기록은 덮어쓰지 않습니다. **임의 테스트만 삭제**는 이 기능으로 생성한 기록만 지우며 기존 예시와 참여 기록은 보존합니다.

직접 참여하는 입력 영역은 기존 `hello stranger`를 유지합니다. B 데이터는 이제 소문자 영문과 단어 사이 공백으로 된 2~80자 문장을 지원합니다. 임의 테스트는 원본 장치 시각(`raw`)을 꾸며 넣지 않고 생성한 상대 시각을 저장하며 `source:"example"`, `b.testKind:"random-sentence"`, `b.seed`로 표시합니다. seed로 생성 결과를 재현할 수 있고, JSON·로컬 저장에는 문장·전체 상대 시각·음높이·좌우·시작 위치를 그대로 보존합니다. 문자 수와 공백 수가 달라도 글자별 음높이를 부여하지 않고 기존처럼 사람별 한 음높이로 재생합니다. 문장 차이는 타격 수·리듬 길이·쉼과 시각화에 반영됩니다. 구두점·한글 입력 및 생성형 AI 연동은 추가하지 않습니다.

- 원본 `performance.now()` keydown과 첫 글자 기준 상대 시각을 저장합니다. 퀀타이즈·속도 변경·길이 정규화가 없습니다. 공백에는 음이 없으므로 기본 `hello stranger`는 13개 음, 임의 테스트는 문장의 비공백 문자 수만큼 음이 납니다.
- 각 기록의 ID로 C3·D3·E3·G3·A3·C4·D4·E4·G4·A4 중 한 음, 약한 pan(-0.3~0.3), 시작 비율(0~1)을 결정하고 JSON의 `b: { midi, pan, startFraction }`에 보존합니다. 복원과 재재생에서도 같으며 매 반복마다 랜덤화하지 않습니다.
- sine oscillator의 attack은 30ms, release는 500ms입니다. 별개 소스로 음을 겹치며 이전 음을 자르지 않습니다. 음별 peak는 0.32, 레이어 gain은 `0.4 / sqrt(레이어 수)`로 부드럽게 조정합니다. 마스터 슬라이더 기본값은 65%, gain 상한은 0.65이며 compressor로 피크를 완화합니다. 기존의 지나치게 낮은 중첩 gain을 높여 여러 트랙을 더 잘 들을 수 있게 했습니다. 조정 상수는 `modes/soundscape-audio.js`의 `SETTINGS`에 있습니다.
- 반복 길이 `L = max(12초, 가장 긴 원본 길이 + 2초)`입니다. 개인 시작 위치는 `startFraction × (L − 개인 길이 − attack − release − 10ms)`여서 잔향까지 구간 안에 들어갑니다.
- 같은 반복 구간 안에서는 `구간 시작 + 개인 위치 + 원본 상대 시각`을 사용합니다. 일정 길이 구간에서는 `최초 구간 시작 + 반복 번호 × L`이며, 길이가 바뀌면 그 경계를 새 기준점으로 삼습니다. 25ms 타이머는 다음 150ms만 준비하고 실제 음은 `AudioContext.currentTime`에 예약합니다. 이벤트별 대기 누적은 없습니다.
- 추가·제거에 따른 반복 길이와 개인 위치 변경은 다음 경계에서 적용합니다. 새 레이어는 약 0.8초 페이드인합니다. 제거한 행은 즉시 사라지지만 해당 구간의 이미 진행 중인 소리는 경계까지 유지될 수 있습니다. 마지막 기록 제거·정지는 즉시 전체 예약을 종료합니다.
- 탭 숨김·창 포커스 이탈·모드 전환은 정지하며 복귀 후 자동 재개하지 않습니다. 타이머가 지연돼도 지난 음을 한꺼번에 재생하지 않습니다.
- 자간은 기본 4px에 `입력 간격(ms) × 0.035px`를 더합니다. 각 공백의 기본 폭(0.28em)은 별도입니다. 공통 계수는 `modes/soundscape-visual.js`의 `SETTINGS`에 있으며 모든 기록에 같습니다. 긴 행은 행 안에서 가로 스크롤합니다.
- 데스크톱(가로 960px 이상)에서는 입력·설정을 왼쪽에 두고 오른쪽에 모든 트랙을 한 화면으로 표시합니다. 최대 20개 행의 높이와 글자 크기는 화면 높이에 맞춰 함께 조정하며, 사람마다 자간 비례계수나 행 너비를 정규화하지 않습니다. 행의 ▶는 개별 듣기, ×는 제거입니다. 개별 듣기 중에도 상단 전체 듣기로 바로 돌아갈 수 있습니다. 재생 중인 트랙은 왼쪽 표시선과 해당 글자 색으로 구분합니다. 예시와 JSON 관리는 왼쪽 접이식 메뉴에 있습니다.
- 모스는 [ITU-R M.1677-1 국제 모스 부호](https://www.itu.int/rec/R-REC-M.1677/en)의 영문자 매핑입니다. 점 1단위·선 3단위·부호 내부 간격 1단위(기본 3px), 문자 사이 기본 3단위, 단어 사이 별도 24px를 사용합니다. 여기에 원본 타이핑 간격의 선형 여백을 추가합니다. 공백은 부호를 만들지 않고 앞뒤 경과 시간을 다음 문자 묶음까지 합산합니다. **표준 모스 송신 타이밍이 아닌 ‘타이핑 간격을 덧붙인 모스 시각화’**입니다. 점·선 개수가 소리 개수를 바꾸지 않습니다.

### B 저장·한도·연결 지점

제출·추가·제거 후 localStorage의 `hello.soundscape.v1`에 저장합니다. 새로고침 후 검증하여 복원하고 소리는 자동 시작하지 않습니다. HTTP와 file://, 다른 포트·브라우저·프로필은 저장 공간이 다를 수 있으므로 발표·이동 전 **전체 기록 JSON 다운로드**로 백업하세요. 저장 권한·용량 문제는 안내하며 메모리 기록은 유지합니다. 손상된 기존 저장값은 복원 실패 시 지우지 않습니다.

B 하단의 **전체 기록 JSON 불러오기**는 `{ schemaVersion:1, mode:"soundscape-b", records:[...] }`를 검증한 뒤 기존 목록에 추가합니다. 같은 ID는 중복하지 않습니다. 한 파일 내부 중복 ID, 잘못된 스키마·문구·시각·원본 불일치·음높이·pan·시작 비율, 2MB 초과·총 20개 초과를 거부하고 기존 기록을 보존합니다. 기록별 입력 길이는 0초 초과~120초입니다. **전체 기록 삭제**에는 명시적 확인이 필요하고 A 데이터는 건드리지 않습니다. JSON 파일에는 원본 절대/상대 시각과 배정 설정이 들어가며 재생용 변환으로 덮어쓰지 않습니다.

화면·소리와 분리된 `HelloSoundscapeData.Store.addRecords()`가 검증과 중복 방지·로컬 저장을 담당합니다. 향후 수집 어댑터는 검증된 기록 배열을 `HelloSoundscape.addRecords(records)`로 전달하면 화면과 다음 오디오 경계에 반영됩니다. 서버·로그인·온라인 다중 접속·음악 API·B WAV 내보내기는 이번 구현에 없습니다.

## 공통 JSON 저장 · 불러오기

네 마디 입력 완료 후 상단 **JSON 다운로드**를 누릅니다. **JSON 불러오기**로 복원하면 A의 리듬, Enter 간격, 선택한 완료 손글씨와 선율 음량도 복원합니다. A에서는 기존 네 마디 형식을 지원합니다. B 전체 기록은 B 화면 하단의 전용 JSON 버튼을 사용합니다. 파일은 서버로 보내지 않습니다. A 공통 목록의 동일 id는 갱신하고 B 누적 목록의 동일 id는 중복 추가하지 않습니다.

`examples/typing-example.json`은 **합성 예시 · 실제 참여자 아님**으로 표시합니다. 화면의 예시 다운로드 후 불러오기로 시험할 수 있습니다.

| 항목 | 의미 |
| --- | --- |
| `schemaVersion` | 현재 `1` |
| `id` | 기록 식별자 |
| `text` | 입력 글자열. A는 `hello` 네 번, 총 20글자 |
| `relativeTimesMs` | 원본 keydown 기준 첫 글자=0인 상대 시각 배열. 글자 수와 길이가 같음 |
| `durationMs` | 원본 첫 글자부터 마지막 글자까지. 배열 마지막 값과 같음 |
| `source` (선택) | `local`, `imported`, `example`. 생략 시 `imported` |
| `raw` (선택) | `clock: "performance.now"`, 원본 `keyDownTimesMs`, 선택적 `enterTimesMs` |
| `a` (선택) | A 전용 네 마디 `bars[].endMs`(각 h→Enter), 선택적 `handwriting: { strokes, volume }` |
| `b` (선택) | B 전용 `midi`, `pan`, `startFraction`. B 입력·재생에서는 필수 |

공통 상대 시각은 **마디 사이 실제 준비 대기까지 포함한 원본**입니다. A의 재생 시각(`Recorder.relative`)은 기존 규칙대로 각 h→Enter를 연결해 준비 대기를 제외합니다. 원본과 재생 변환을 섞어 저장하지 않습니다. 손글씨는 정규화 x/y와 원래 down/move/up 시각을 저장하고, 선율은 불러올 때 다시 계산합니다. WAV는 JSON과 별도이며 기존 JSON 저장 형식은 없었으므로 이번 버전부터 schemaVersion 1을 사용합니다.

불러오기는 2MB 제한, 스키마 버전·id·글자 수·이벤트 수·유한한 숫자·시각 순서·첫 시각·전체 길이·원본과 상대 시각 일치·A 마디와 획 데이터를 검증합니다. 모든 검증이 끝난 뒤 적용하므로 잘못된 파일이 기존 기록을 지우지 않습니다. 공통 형식은 최대 256글자/1시간, A 손글씨는 최대 1,000획/50,000점입니다.

## 실행과 사용

**간단 실행:** `index.html`을 더블클릭해 Chrome 또는 Edge에서 열면 됩니다. 서버 없이도 네 드럼 음원을 불러옵니다. `index.html`만 따로 옮기지 말고 프로젝트 폴더 전체를 유지하세요.

개발·자동 검증 시에는 이 폴더에서 다음 명령을 실행하고 <http://localhost:8000>을 엽니다. 종료는 `Ctrl+C`.

```powershell
python -m http.server 8000 --bind 127.0.0.1
```

먼저 시작 화면에서 **A · 인사 오케스트라**를 선택합니다.

1. 영문 입력 모드로 전환하고 **입력 시작**을 누릅니다.
2. 자신의 속도로 소문자 `hello`를 입력하고, 원하는 간격을 두고 **Enter**를 누릅니다. 이를 **네 번** 반복합니다. 두 `l`은 키를 뗐다가 다시 누릅니다. 입력 중에는 소리가 나지 않고 네 줄 모두 일정한 자간을 유지합니다.
3. 첫 세 Enter는 다음 마디로 이동하고, **네 번째 Enter**에서만 전체 기록을 완료합니다. 완료 후 네 줄 각각의 입력 간격에 따른 자간과 마디별 시간표를 표시합니다. 긴 결과는 글자 영역 안에서 가로로 스크롤합니다.
4. **리듬 듣기**를 누르면 1→2→3→4마디 전체, 총 20타격을 **정지할 때까지 반복 재생**하며 해당 줄·글자의 색이 잠깐 바뀝니다. 매 마디의 킥 → 스네어 → 하이햇 → 하이햇 → 톰 순서와 입력 간격을 보존합니다. 각 마디의 `o`에서 다음 마디의 `h`까지는 그 마디에서 기록한 **o → Enter 간격**입니다. 4마디 끝에서는 1마디로 돌아갑니다. Enter 자체에는 소리나 추가 글자를 배정하지 않습니다.
5. **정지**는 현재 소리·미래 예약·시각 반응을 취소하고 기록은 유지합니다. **다시 입력하기**는 이를 모두 취소하고 기록을 지운 뒤 입력 영역으로 포커스를 옮깁니다.

### 선택 기능: 손글씨로 선율 만들기

네 마디 입력 후 **리듬만 듣기**를 바로 사용할 수 있습니다. **손글씨 선율 추가하기**를 선택하면 Canvas가 열립니다. 마우스나 터치패드를 눌러 드래그하며 hello 또는 다른 인사말을 자유롭게 쓰세요. 여러 획을 쓸 수 있으며 문자 인식은 하지 않습니다. **쓰기 완료 → 함께 듣기** 순서로 타악기와 선율을 함께 듣습니다. 완료 후 다시 쓰려면 **지우고 다시 쓰기**, 생략하려면 **선율 없이 돌아가기**를 누릅니다. 음량 슬라이더는 선율에만 적용됩니다.

사용자 선택에 따라 **기존 네 마디 입력과 반복 재생을 유지**합니다. 함께 듣기도 동일한 네 마디 주기로 반복합니다. 손글씨를 생략하거나 삭제해도 리듬 기록과 리듬만 듣기는 유지됩니다. 정지·재입력·필기 삭제·선율 없이 돌아가기·창 포커스/탭 이탈은 현재 및 미래 소리와 두 시각화의 RAF를 취소합니다.

Canvas 좌표는 0~1로 정규화합니다. 아래부터 위까지 C4·D4·E4·G4·A4·C5 여섯 구역이며 y방향을 반전합니다. 가로 좌표는 그림과 재생 점 위치에만 사용하고 음 순서를 정렬하지 않습니다. 각 획은 down/move/up을 저장하며 pointer capture로 바깥에서 떼는 동작도 처리합니다. 취소된 포인터의 미완성 획은 버립니다. 원래 필기 경로는 유지하고 음높이 계산에만 25ms 시정수의 평활화와 캔버스 높이 2% 히스테리시스를 적용합니다. 같은 구역은 한 음을 유지하고 다른 구역으로 이동하면 이전 음을 종료합니다. 같은 높이의 새 획은 새 음이며, 획 사이에는 쉼을 둡니다.

- **T**: 기존 네 마디 재생 시간축에서 첫 h부터 네 번째 hello의 마지막 o까지(`recorder.relative.at(-1)`). 마지막 o→Enter 시간은 T에서 제외합니다. 타이핑 입력 간격과 마디 연결 규칙은 바꾸지 않습니다.
- **H**: 첫 pointerdown부터 마지막 pointerup까지. 획 사이 쉼은 포함하고 쓰기 완료 버튼을 누르기 전 마지막 대기는 제외합니다.
- 음의 시작·끝과 경로 재생 시각 모두 `(필기 경과 시간 / H) × T`로 변환합니다. 예: H=4000ms, T=1000ms이면 2000ms 지점은 500ms입니다. 타악기 타격에 스냅하거나 길이를 늘리지 않습니다. T<500ms이면 더 천천히 타이핑하라는 안내를 표시합니다. T/H가 0·비정상이거나 빈 입력·점만 있는 입력·미완성 획이면 변환하지 않습니다.

선율은 기존 AudioContext에서 triangle oscillator를 사용합니다. 타악기와 같은 `currentTime + 60ms`를 시작점으로 예약하고 음의 공격은 최대 8ms, 펜을 떼거나 음을 바꾼 뒤 release는 20ms입니다. 기본 선율 gain은 0.07이고 슬라이더는 0~0.15 범위입니다. 종료나 다음 반복에서 음의 꼬리를 강제로 끊지 않습니다. 마지막 o→Enter 동안 새 선율은 없지만 release나 타악기 잔향이 남을 수 있습니다. 재생 점은 같은 오디오 시계의 주기별 위상을 사용하고 획 사이 쉼에는 표시하지 않습니다. 화면 크기를 바꿔도 정규화한 경로를 다시 그리며 별개 획을 직선으로 연결하지 않습니다.

음원 준비 전에는 재생할 수 없습니다. 실패하면 파일명·HTTP 오류 또는 디코딩 원인과 **음원 다시 불러오기** 버튼을 표시합니다. HTTP 요청 제한 시간은 10초입니다. 폰트 로딩에 실패하면 Georgia → Times New Roman → 시스템 serif 순으로 대체하며 입력·재생을 차단하지 않습니다.

파일을 직접 여는 `file://`에서는 브라우저가 WAV의 `fetch()` 요청을 차단하므로, `assets/drums/embedded.js`에 포함한 동일 WAV 바이트를 디코딩합니다. HTTP 실행에서는 기존 WAV 파일을 요청합니다. 내장 데이터도 동일한 CC0 음원이며 합성음으로 대체하지 않습니다. 음원을 변경하면 `python scripts/build-embedded.py`로 내장 파일을 다시 만들고 `python scripts/build-embedded.py --check`로 원본과 일치하는지 확인하세요. 브라우저 보안 설정을 변경할 필요가 없습니다.

오타·대문자·붙여넣기·조합 입력·키 자동 반복은 기록하지 않습니다. Backspace 수정은 지원하지 않습니다. 입력 영역이나 창이 포커스를 잃으면 시도를 취소합니다. 기록은 페이지 메모리에만 남습니다.

## WAV 다운로드

네 마디 입력이 끝나면 **원본 WAV 다운로드**와 **반복 WAV 다운로드**가 표시됩니다. 손글씨는 **쓰기 완료**로 변환한 선율만 포함하며, 생략·삭제한 경우 리듬만 저장합니다. 버튼 옆에 포함 내용, 반복 횟수와 예상 파일 길이를 표시합니다. 원하는 선율 음량을 정한 뒤 다운로드하세요.

- `greeting-original.wav`: 현재 네 마디와 선택한 선율을 한 번 재생한 파일.
- `greeting-repeated.wav`: 같은 내용을 완전한 단위로 반복한 파일. 음악 구간이 가능하면 15~20초에 들어오도록 17.5초에 가까운 반복 횟수를 선택합니다.
- 형식은 **44.1kHz · 16bit signed little-endian PCM · 스테레오 RIFF/WAV**입니다. 원래 샘플과 triangle 음색·공격·release·음량을 유지합니다. 클리핑 이전 피크가 1을 초과할 때만 전체 채널에 `0.999 / peak`를 동일하게 적용하며, 작게 녹음된 결과를 증폭하거나 정규화하지 않습니다.

내보내기는 기존 화면 재생과 같은 `HelloRhythm.buildEvents()`와 `scheduleEvents()`를 사용합니다. 재생과 동일한 60ms 준비 구간 뒤 첫 타격을 배치하고, 실제 샘플 길이와 선율 release를 모두 계산한 뒤 끝에 100ms 여유를 붙입니다. 렌더링에는 **OfflineAudioContext**만 사용하며 다운로드를 시작하면 현재 스피커 재생을 정지합니다. 렌더 중에는 두 다운로드 버튼과 입력·선율 변경을 잠그고, 완료나 실패 후 다시 사용할 수 있게 합니다.

반복 파일에서 **T는 기존 네 마디 시간축의 첫 h부터 마지막 o까지**이고, 반복 시작 간격은 `T + 0.5초`입니다. 이는 화면의 실시간 루프(o→Enter 간격)와 별개의 내보내기 규칙입니다. `modes/orchestra-wav.js`의 `SETTINGS.repeatGapSeconds` 한곳에서 0.5초를 조절할 수 있습니다. 모든 반복의 타격·선율 시작과 종료 간격을 유지하며, 마지막 o와 다음 h 사이의 시작 간격은 0.5초입니다. 잔향은 다음 반복과 겹칠 수 있고 강제로 끊지 않습니다.

완전한 단위만 저장하므로 정확히 목표 길이에 맞추려 재생 속도를 바꾸거나 마지막 반복을 자르지 않습니다. 한 단위의 잔향까지 포함한 길이가 20초를 넘으면 한 번만 저장합니다. 긴 단위 때문에 15~20초 안에 맞는 정수 반복 횟수가 없는 경우에는 그 구간에 가장 가까운 완전한 길이를 선택하고 버튼 옆에 안내합니다. 파일에는 60ms 준비 시간과 마지막 100ms 여유도 들어가므로 표시한 음악 구간보다 약간 길 수 있습니다. 브라우저 메모리를 위해 10분을 넘는 렌더는 안내 후 거부합니다.

다운로드 후 브라우저 다운로드 목록에서 파일을 확인하고 원하는 음악 생성 서비스에 직접 업로드하면 됩니다. 외부 서비스 API 호출이나 자동 업로드는 없습니다. 업로드에 관한 서비스별 제한은 이 앱에서 처리하지 않습니다. WAV는 브라우저 메모리에서 생성되며 다운로드가 끝난 Blob URL은 해제합니다.

## 시간과 시각화

`Recorder.bars`에 네 개의 `BarRecorder`를 저장합니다. 각 마디의 `times`는 다섯 글자의 원래 `performance.now()` keydown 시각, `relative`는 그 마디 첫 `h` 기준 상대 시각, `gaps`는 네 글자 간격입니다. `enterTime`은 Enter keydown 시각, `loopGapMs`는 `enterTime - times[4]`, `durationMs`는 `enterTime - times[0]`입니다. 각 마디는 `o` 뒤 Enter로 완료하며 네 마디가 모두 끝나야 재생할 수 있습니다. 조기 Enter, 길게 누르기와 조합 중 Enter는 기록하지 않습니다.

전체 `Recorder.relative`는 앞 마디들의 `durationMs` 합에 해당 마디의 상대 시각을 더한 20개 시각입니다. 전체 길이는 네 마디 길이의 합입니다. 첫 글자까지 기다린 시간과 **Enter 뒤 다음 hello를 준비하는 대기 시간은 제외**하고 각 마디의 h→Enter 구간을 그대로 이어 붙입니다. 마디 길이를 같게 만들거나 BPM에 맞추지 않습니다. 계산에는 원래 정밀도를 유지하며 화면에서만 0.1ms로 반올림합니다.

`modes/orchestra-audio.js`의 `SPACING` 한곳에서 자간을 조절합니다.

```js
const SPACING = Object.freeze({ minimumPx: 12, pixelsPerMs: 0.12 });
// 각 글자 왼쪽 추가 여백 = 12px + 앞 글자와의 입력 간격(ms) × 0.12
```

예시 상대 시각 `[0,180,420,570,900]ms`의 간격은 `[180,240,150,330]ms`, 추가 여백은 `[33.6,40.8,30,51.6]px`입니다. 입력 중에는 네 여백을 모두 12px로 유지합니다. 완료 후 각 글자의 margin을 따로 설정하며 글자 크기·글자 자체의 폭은 바꾸지 않습니다. 모든 기록에 같은 계수를 적용하고 화면 폭에 맞춘 정규화나 간격 상한을 두지 않습니다.

음원은 `OfflineAudioContext`로 미리 디코딩하고 메모리에 저장합니다. 클릭으로 만든 `AudioContext`가 suspended이면 resume합니다. 첫 타격은 `currentTime + 60ms`, 나머지는 여기에 `relative / 1000`을 더해 `AudioBufferSourceNode.start()`로 한 번에 예약합니다. 속도 변경·박자 보정·연속 setTimeout 재생은 없습니다. 모든 타격은 별개의 소스이며 자연스러운 꼬리가 끝날 때까지 겹쳐 재생됩니다.

루프 주기는 `네 마디의 durationMs 합 / 1000`입니다. 예를 들어 1마디의 `o`가 900ms, Enter가 1200ms이면 2마디 h는 첫 h 기준 1200ms에 시작합니다. 마지막에는 4마디의 o→Enter 간격 후 1마디로 돌아갑니다. 고정 대기 시간이나 샘플 꼬리 길이를 추가하지 않습니다. 기록한 끝 간격이 0ms면 다음 h는 o와 동시에 시작할 수 있으며 원래 소리를 강제로 끊지 않습니다. 전체 주기까지 0ms인 유효하지 않은 기록은 재입력을 안내합니다. 25ms마다 다음 200ms 안에 시작하는 네 마디 묶음을 미리 예약하며 실제 소리는 오디오 시간축의 `최초 시작 + 반복 번호 × 루프 주기`에 시작합니다. 정지·재입력은 반복 타이머, 현재·미래 소스, 시각 반응을 모두 취소합니다. 브라우저가 백그라운드 탭의 타이머를 오래 지연시키면 지난 패턴을 몰아서 재생하지 않고 원래 시간축의 다음 패턴부터 재개합니다.

시각 반응은 `requestAnimationFrame`에서 같은 `AudioContext.currentTime`을 읽어 해당 인덱스를 120ms 동안 강조합니다. 두 `l`은 별개 이벤트이며, 아주 빠르면 강조 구간도 겹칠 수 있습니다. CSS는 색만 바꾸고 위치·크기·여백을 바꾸지 않습니다. 정지 시 RAF와 타임라인을 지우고 이전 콜백도 무효화합니다. 화면 갱신은 디스플레이 주기에 제한되며 실제 소리와 화면에는 기기별 출력 지연이 있을 수 있습니다.

## 검증

2026-10-18 B 추가 후 Chrome headless에서 A/B 자동 검증 **176/176**, A file:// 입력·손글씨·WAV 검증을 수행했습니다. B 데이터 검증·ID·한도·저장 거부·14자 입력·13음·모스·자간·경계 추가/제거·지연된 타이머·resume 중 정지·시각 전환·모드 정리를 포함합니다. `python scripts/verify-soundscape.py`는 별도 임시 프로필에서 HTTP/file:// 각각 **실제 AudioContext로 20개 레이어를 한 주기 끝까지 재생**하고, 260개 이벤트의 순서·시각과 다음 반복 시작 간격을 비교합니다. 실제 JSON 다운로드·File 불러오기·페이지 새로고침 후 복원 및 자동 재생 없음도 확인합니다.

공유된 B 음 생성·gain·compressor 로직의 실제 OfflineAudioContext 파형 검증에서 1/5/10/20레이어 피크는 각각 약 0.1319/0.1504/0.1635/0.2050(마스터 최대, 빠른 입력 시험)으로 클리핑이 없었습니다. 20개 기록의 동일 음높이 260음을 동시에 집중시킨 시험도 피크 0.416으로 클리핑이 없었습니다. 1280×800에서 자간·모스 모두 20개 트랙이 한 화면에 들어가는지도 확인했습니다. 이는 특정 시험 파형의 측정이며 청감 평가를 대신하지 않습니다. 실제 스피커에서의 음량·음색·좌우 배치·긴 시간 재생, 브라우저별 자동 재생 정책과 물리 키보드/IME는 수동 확인 항목입니다.

```powershell
python scripts/verify-browser.py
python scripts/verify-downloads.py
python scripts/verify-soundscape.py
```

구조 변경 후 기존 입력·반복키 무시·두 l·재생·손글씨 생략·자간·WAV 검증을 유지했습니다. 추가 검증은 JSON 원본/재생 시각 구분, 소수 시각 보존, 잘못된 파일 거부와 기존 기록 보존, 손글씨 복원, 동일 id 갱신, 실제 File 입력, 모드 전환 중 파일 읽기/렌더 취소, 소리·RAF·키 리스너 해제, 반복 전환 시 중복 방지, B 단독 진입(오디오 API 없음)을 포함합니다.

`python scripts/verify-downloads.py`는 실제 JSON 파일을 다운로드하여 20개 원본 시각·전체 길이·손글씨·음량을 확인하고 WAV 두 파일도 검사합니다. 네이티브 입력 장치와 스피커 직접 청취는 아래 수동 확인 항목에 해당합니다.

서버 실행 후 <http://localhost:8000/tests.html>을 열면 자동 검증합니다. 검증 중에는 창을 조작하지 마세요. Chrome이 설치된 Windows에서는 `python scripts/verify-browser.py`로 HTTP와 file:// 테스트를 함께 실행할 수 있습니다. 다른 Chromium 경로는 환경 변수 `HELLO_TEST_BROWSER`로 지정합니다. 2026-10-17 Chrome headless에서 **133/133 통과**, 별도 file:// 입력·손글씨·함께 듣기·삭제·정지·재입력 검증도 통과했습니다. 1280×2000 화면 이미지로 손글씨 구역·음 이름·획·컨트롤 배치를 확인했습니다.

WAV 검증은 헤더·비트 깊이·채널·길이, 실제 WAV 디코딩, 실시간 재생 로직과의 파형 비교, 반복별 20타격의 시작 시각과 샘플, 잔향과 마지막 무음 여유, 동일 감쇠·클리핑 방지, 선율 생략, 샘플 미준비와 렌더 실패 안내, 중복 클릭 차단 및 재시도 복구를 포함합니다. `python scripts/verify-downloads.py`는 별도 임시 Chrome 프로필에서 **실제로 두 파일을 다운로드**하고 Python `wave`로 검사합니다. 테스트 결과 원본 **5.66002초**, 반복 **15.66002초**, 모두 스테레오 44100Hz·PCM16이며 피크는 각각 8296/32768과 8628/32768, 마지막 80ms는 무음이었습니다. 스피커용 AudioContext 생성을 막은 상태에서도 렌더·다운로드에 성공했습니다. 검증 파일과 프로필은 임시 폴더에서만 생성하고 검사 후 제거합니다.

기존 네 마디·악기·자간 검증을 유지하고, 손글씨의 6음 매핑, 오른쪽→왼쪽 입력 순서, 같은 구역 유지, 경계 떨림 억제, 획 사이 쉼과 동일 높이의 새 획, H=4초/T=1초 변환, 잘못된 입력·짧은 T 처리를 추가했습니다. 합성 Pointer Events로 정규화 좌표·포인터 취소·크기 변경을 확인했습니다. 공통 오디오 시작과 음 시작/끝/release, 음량 조절, 선율 생략·삭제·화면 이탈, RAF 재생 점의 쉼·반복·취소도 확인했습니다. 실제 OfflineAudioContext 렌더에서 리듬만 파형과 함께 듣기 파형을 비교해 선율 출력·낮은 음량·pen-up 무음과 정지 후 전체 무음을 검증했습니다.

직접 열기 오류도 수정 전 `file://`에서 재현한 뒤 수정 후 검증했습니다. 실제 `index.html`의 음원·폰트 준비 완료를 확인했고, 같은 앱에 `scripts/file-smoke.js`를 추가한 임시 검증 페이지에서 fetch를 차단한 상태로 네 음원 디코딩·실제 오프라인 오디오 렌더·네 마디 입력 완료·재생·정지·재재생·초기화를 확인했습니다. 네 마디 완료 화면은 1280×1400 이미지로 렌더해 네 줄 자간과 결과표 배치도 확인했습니다. 자동 재생 조작에는 headless 검증용 autoplay 허용 옵션을 사용했으며, 일반 사용자 화면에서는 기존과 같이 재생 버튼 클릭으로 AudioContext를 활성화합니다. 실제 스피커 청취는 수행하지 않았습니다.

- 기존 입력 계산, 오타·조합·반복 키 무시, 첫 글자 대기 제외와 두 `l`의 keyup 구분.
- 악기 순서, 동일 하이햇 버퍼의 별도 타격, 원래 예약 시각, 빠른 입력 시 소리 겹침, 악기별 gain.
- 실제 로컬 WAV 네 개의 fetch·디코딩과 피크 정규화.
- **실제 Web Audio 오프라인 렌더**를 각 음의 기대 시작 시각에 합산한 PCM 파형과 비교하여 순서·간격·겹침 보존 확인. 정지 후 미래 음 예약의 렌더 결과가 무음임을 확인.
- 공통 선형 자간, 같은 간격의 같은 여백, 입력 중 고정 자간, 긴 간격의 영역 내 스크롤, 강조 전후 위치·폭·높이 불변.

- 음원 HTTP 오류·손상된 파일, 실패 후 재시도, 준비 전 재생 차단. 별도 실제 앱 인스턴스에서 음원 실패 안내·재시도와 폰트 404 대체 처리 확인.

**직접 확인하지 않은 수동 항목:** 실제 마우스·터치패드의 드래그 감촉, OS가 보내는 pointer capture·펜 떼기·창 밖 드래그, 스피커에서 들리는 triangle 선율의 음색·타악기와의 균형·체감 동기·정지 후 무음, 물리 키보드·OS IME와 실제 suspended AudioContext의 클릭 활성화. 다운로드 WAV의 실제 청취(재생과의 체감 일치, 반복 경계, 잔향·클릭 잡음), 외부 음악 서비스의 업로드·수용 여부도 직접 확인하지 않았습니다. 자동 UI 테스트는 합성 키/Pointer Events와 오디오 모형을 사용하고, 파형 테스트는 실제 브라우저의 오프라인 오디오 엔진을 사용합니다. 실제 장치 입력이나 스피커 청취를 수행한 결과는 아닙니다.
