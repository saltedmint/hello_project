## 실제 공개 서버 확인

저장소·쿠키가 분리된 Chrome 컨텍스트 두 개가 공개 HTTPS 주소에 접속했다. 한 컨텍스트는 데스크톱, 다른 하나는 390 × 844 모바일 화면을 사용했다. 물리 기기 두 대로 확인한 것은 아니다. 입력은 합성 DOM 이벤트이며 실제 키보드·IME 타격을 대신하지 않는다.

- 각 세션의 세 질문 답변을 실제 서버에 저장했다.
- 두 번째 세션의 결과 스냅샷에 첫 번째 세션이 포함됐다.
- 첫 세션을 새로고침한 뒤에도 두 기록이 조회됐다.
- 동일 세션을 다시 POST해도 한 건만 존재했다.
- 9개 결과 구간과 내 기록 한 번 포함, 지속 앰비언스 하나를 확인했다.
- 390px에서 시작·입력·다음 버튼이 화면에 들어왔다.
- 비로그인 관리자 내보내기, 인증 헤더 위조 요청을 403으로 차단했다.
- 네트워크 실패를 **모의 주입**했을 때 미전송 기록이 브라우저에 남고 개인 결과로 진행됐다. 실제 서버로 재시도해 저장됐다.

별도 QA 회차에서 실제 HTTPS/D1 API 검사 **12개**도 통과했다(`scripts/verify-live-api.mjs`).

- 세 답변 단위 저장, 서버 생성 시각, 동일 요청 재시도, 다른 내용 덮어쓰기 거부, 잘못된 시각 거부.
- 더미 배치 두 번 등록 후 합성 10명·30답변과 검증 참가자 1명·3답변만 존재.
- 관리자 내보내기의 전체 11세션·33답변 및 원본 활동·문자·제출 시각이 입력과 정확히 일치.
- 공개 응답에서 답변 원문·문자·키·수정 로그를 제외.
- 더미 배치만 제거한 뒤 검증 참가자 기록 유지. 공개 삭제·내보내기 거부.

QA 회차는 합성 검증임을 제목으로 구분했다. 검증이 끝나면 해당 응답만 제거하고 기존 관객 회차 `presentation-2026`으로 복구했다. 실제 관객 데이터·로컬 JSON은 업로드하거나 덮어쓰지 않았다. 비활성 QA 회차 메타데이터만 남아 있으며 발표 누적 조회에는 포함되지 않는다.

## 발표 전 직접 확인

실제 휴대폰에서 모바일 데이터로 QR을 열고 터치 시작→소리 켜짐→한글 입력→다음→결과→복귀를 한 번 진행한다. iOS Safari/Android Chrome의 실제 가상 키보드·한국어 IME·자동완성과 스피커/이어폰 청취는 자동 검증하지 못했다. 노트북 Enter 제출도 확인한다. 실제 발표자 계정으로 관리 화면에 로그인해 JSON 내보내기를 확인한다. 서버 측 관리자 토큰 검증은 통과했지만 대화형 사용자 로그인은 사용자가 직접 진행해야 한다.

발표 회차 변경·더미 포함 여부는 관리 화면에서 설정한다. 기본은 실제 응답만 포함하며, 더미는 자동 추가하지 않는다. 공개 원문 비반환은 모스 부호로부터의 내용 추론까지 막는 기밀화가 아니므로 민감한 내용을 쓰지 않도록 안내한다.
